## 1. 本节内容

- 了解 Vite 中 CSS Modules 的使用方式
- 掌握局部作用域和命名规则的配置
- 理解 TypeScript 中 CSS Modules 的类型声明

## 2. 评价

- CSS Modules 是 Vite 中实现样式隔离的推荐方案，开箱即用无需额外配置
- 相比 Scoped CSS（Vue）和 CSS-in-JS，CSS Modules 更轻量且性能更好

## 3. `.module.css`

- 以 `.module.css` 为后缀的文件会被 Vite 自动识别为 CSS Modules

```ts
import styles from './App.module.css'

document.getElementById('app')!.className = styles.container
```

- 同样支持 `.module.scss`、`.module.less`、`.module.styl` 等预处理器后缀
- CSS Modules 的核心：将类名编译为唯一的哈希字符串，避免全局样式冲突

## 4. 局部作用域

- CSS Modules 中的类名默认是局部的，不会污染全局

```css
/* App.module.css */
.title {
  color: red;
}
```

```ts
import styles from './App.module.css'
// styles.title 为编译后的唯一类名，如 '_title_1a2b3_1'
```

- 如果需要定义全局样式，使用 `:global()` 伪类：

```css
:global(.ant-btn) {
  /* 全局样式，不会被模块化 */
}

/* 混合使用 */
.wrapper :global(.ant-btn) {
  /* .wrapper 是局部的，.ant-btn 是全局的 */
}
```

## 5. 命名规则

- CSS Modules 的类名生成规则可通过 `css.modules` 配置：

```ts
export default defineConfig({
  css: {
    modules: {
      // 将 kebab-case 转为 camelCase（便于 JS 访问）
      localsConvention: 'camelCaseOnly',
      // 自定义类名格式
      generateScopedName: '[name]__[local]___[hash:base64:5]',
    },
  },
})
```

- 默认规则：`[hash:base64:8]`（8 位 Base64 哈希）
- 推荐的命名格式：`[local]_[hash:base64:5]`（保留原始类名 + 哈希，便于调试）

## 6. TypeScript 类型声明

- TypeScript 无法识别 `.module.css` 文件的类型，需要添加声明文件
- 创建 `src/env.d.ts` 或 `src/vite-env.d.ts`：

```ts
declare module '*.module.css' {
  const classes: { readonly [key: string]: string }
  export default classes
}

declare module '*.module.scss' {
  const classes: { readonly [key: string]: string }
  export default classes
}

declare module '*.module.less' {
  const classes: { readonly [key: string]: string }
  export default classes
}
```

- 使用 `camelCaseOnly` 后，类名在 TS 中以 camelCase 形式访问
- Vite 模板项目通常已包含此声明（在 `env.d.ts` 中）
