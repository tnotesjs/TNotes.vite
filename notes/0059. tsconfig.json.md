## 1. 本节内容

- 了解 Vite 项目中 `tsconfig.json` 的关键配置项
- 掌握 `compilerOptions` 中各选项的作用和推荐值
- 理解 `paths`、`moduleResolution` 等配置与 Vite 的关系

## 2. 评价

- `tsconfig.json` 的配置直接影响 IDE 的类型检查行为和路径解析
- Vite 模板生成的 `tsconfig.json` 通常已经是最优配置，不建议随意修改

## 3. `compilerOptions`

- Vite 项目推荐的 `compilerOptions` 配置：

```json
{
  "compilerOptions": {
    "target": "ES2020",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "strict": true,
    "jsx": "react-jsx",
    "resolveJsonModule": true,
    "isolatedModules": true,
    "esModuleInterop": true,
    "lib": ["ES2020", "DOM", "DOM.Iterable"],
    "skipLibCheck": true,
    "noEmit": true
  }
}
```

- 关键选项说明：
  - `target`：编译目标语法版本
  - `module`：输出模块格式
  - `strict`：启用严格类型检查（推荐开启）
  - `isolatedModules`：确保每个文件可被单独转译（Oxc 转换器的要求）
  - `noEmit`：不输出编译产物（由 Vite/Ebuild 处理）

## 4. `paths`

- 配置 TypeScript 的路径别名，与 `vite.config.ts` 中的 `resolve.alias` 对应
- 两者需要同步配置，否则会出现 IDE 不报红但运行时失败的问题

```json
{
  "compilerOptions": {
    "baseUrl": ".",
    "paths": {
      "@/*": ["src/*"],
      "@components/*": ["src/components/*"],
      "@utils/*": ["src/utils/*"]
    }
  }
}
```

- 对应的 `vite.config.ts` 配置：

```ts
import { resolve } from 'path'

export default defineConfig({
  resolve: {
    alias: {
      '@': resolve(__dirname, 'src'),
      '@components': resolve(__dirname, 'src/components'),
      '@utils': resolve(__dirname, 'src/utils'),
    },
  },
})
```

## 5. `baseUrl`

- 设置非相对路径导入的基准目录
- 通常设置为 `"."`（项目根目录）
- 配合 `paths` 使用，实现路径别名功能

```json
{
  "compilerOptions": {
    "baseUrl": "."
  }
}
```

- 注意：`baseUrl` 不要设置为 `src`，这会导致 `node_modules` 中的包解析出问题

## 6. `types`

- 指定需要包含的类型声明文件
- Vite 项目通常需要包含以下类型：

```json
{
  "compilerOptions": {
    "types": ["vite/client"]
  }
}
```

- `vite/client` 提供了以下类型声明：
  - `import.meta.env` 的类型定义
  - 静态资源导入的类型（`.png`、`.svg`、`.css` 等）
  - HMR API 的类型
- 如果使用了其他全局类型库，也可以在此添加

## 7. `jsx`

- 配置 JSX 的转换方式
- 常用值：
  - `"react-jsx"`：React 17+ 的自动导入模式（推荐）
  - `"preserve"`：保留 JSX 语法（交给 Vite/Oxc 处理）
  - `"react"`：经典模式，需要手动 `import React`
  - `"react-jsxdev"`：React 开发模式的 JSX 转换
- Vue 项目通常设置为 `"preserve"`

## 8. `moduleResolution`

- 配置 TypeScript 的模块解析策略
- Vite 推荐使用 `"bundler"` 模式：

```json
{
  "compilerOptions": {
    "moduleResolution": "bundler"
  }
}
```

- `bundler` 模式的优势：
  - 兼容 ESM 和 bundler 的解析行为
  - 支持 `package.json` 的 `exports` 字段
  - 允许省略文件扩展名
  - 与 Vite 的模块解析行为一致
- 其他可选值：
  - `"node"`：传统的 Node.js 解析策略（不推荐）
  - `"node16"` / `"nodenext"`：Node.js ESM 解析策略
