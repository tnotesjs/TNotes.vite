## 1. 本节内容

- 了解 `public` 目录的作用和使用方式
- 理解 `public` 目录与 `src/assets` 的区别
- 掌握 `public` 目录的适用场景

## 2. 评价

- `public` 目录和 `src/assets` 的分工明确：前者放"不需要处理"的资源，后者放"需要处理"的资源
- 选错目录可能导致资源路径错误或构建行为不符合预期

## 3. `public` 的作用

- `public` 目录中的文件会被原样复制到构建产物的根目录
- 不经过 Vite 的任何处理（不压缩、不添加哈希、不内联）
- 配置项 `publicDir` 可以修改此目录的名称或禁用（设为 `false`）
- 目录中的文件在开发环境和生产环境都可以通过根路径 `/` 直接访问

## 4. 访问路径

- 在 HTML 中引用：`<link rel="icon" href="/favicon.ico">`
- 在 JS 中引用：`fetch('/data/config.json')`
- 在 CSS 中引用：`background: url('/images/bg.png')`
- 注意路径以 `/` 开头，从根目录开始解析
- 如果配置了 `base`，需要加上 base 前缀：

```ts
// base 为 '/my-app/' 时
const url = `${import.meta.env.BASE_URL}favicon.ico`
// 结果：'/my-app/favicon.ico'
```

## 5. 与 `src/assets` 的区别

| 维度       | `public/`              | `src/assets/`                    |
| ---------- | ---------------------- | -------------------------------- |
| 构建处理   | 原样复制               | 被 Vite 处理（哈希、压缩、内联） |
| 文件名     | 保持不变               | 添加内容哈希（利于缓存）         |
| 导入方式   | 通过绝对路径 `/` 引用  | 通过 `import` 或相对路径引用     |
| 小文件内联 | 不会内联               | 小于 4KB 自动 Base64 内联        |
| HMR        | 不支持（需手动刷新）   | 支持                             |
| 适用场景   | 必须保持原始路径的文件 | 需要优化的图片、字体等           |

## 6. 适用场景

- 适合放在 `public/` 的文件：
  - `favicon.ico`、`robots.txt`、`sitemap.xml`（必须在根路径）
  - PWA 的 `manifest.json` 和 Service Worker 文件
  - 第三方 SDK 脚本（如 Google Analytics）
  - 大体积的媒体文件（视频、PDF），避免被构建工具编码处理增加内存消耗
  - 需要通过固定路径访问的 JSON 配置文件
- 适合放在 `src/assets/` 的文件：
  - 项目中引用的图片、图标
  - 字体文件
  - 需要被构建工具优化和添加哈希的任何资源
