## 1. 本节内容

- 了解 Vite 生产构建中 Tree Shaking 的工作原理
- 理解 ESM 与 Tree Shaking 的关系
- 掌握副作用标记和 `sideEffects` 配置

## 2. 评价

- Tree Shaking 是减小产物体积的重要手段，Vite 默认启用
- 确保项目使用 ESM 格式是 Tree Shaking 生效的前提

## 3. ESM 与 Tree Shaking

- Tree Shaking 依赖 ESM 的静态 `import`/`export` 语法
- 为什么 CJS 无法 Tree Shaking：
  - `require()` 是动态的，可以在条件语句中调用
  - `module.exports` 可以在运行时修改
  - 打包器无法在编译时确定哪些导出被使用
- ESM 的优势：
  - `import`/`export` 是静态声明，编译时即可确定依赖关系
  - 模块的导出是只读的，不会在运行时变化
- Rolldown 的 Tree Shaking 能力在所有打包器中最为出色

## 4. 副作用标记

- 副作用（Side Effect）是指模块执行时对外部状态的影响
- 有副作用的模块不能被 Tree Shaking 移除
- 常见的副作用：
  - 修改全局变量：`window.xxx = ...`
  - 导入 CSS：`import './style.css'`
  - Polyfill：`import 'core-js/stable'`
  - 原型链修改：`Array.prototype.xxx = ...`

## 5. `sideEffects`

- 在 `package.json` 中声明包的副作用：

```json
{
  "name": "my-lib",
  "sideEffects": false
}
```

- `sideEffects: false`：声明包没有副作用，打包器可以安全地移除未使用的导出
- `sideEffects: ["*.css", "./src/polyfill.js"]`：声明只有指定文件有副作用
- 作为库的作者，正确设置 `sideEffects` 可以帮助消费者的打包器更好地 Tree Shaking

## 6. 常见失效场景

- Tree Shaking 失效的常见原因：
  - 使用 CommonJS 格式（`require` / `module.exports`）
  - 使用了有副作用的导入（如 `import 'xxx'` 不带绑定）
  - 依赖包没有正确设置 `sideEffects`
  - 使用了 Babel 的某些插件（可能将 ESM 转为 CJS）
  - 动态导入的路径无法静态分析
- 排查方法：
  - 使用 `rollup-plugin-visualizer` 分析产物组成
  - 检查产物中是否包含未使用的代码
  - 确认依赖包的 `package.json` 中 `module` 或 `exports` 字段指向 ESM 入口
