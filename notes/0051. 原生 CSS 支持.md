## 1. 本节内容

- 了解 Vite 对原生 CSS 的开箱即用支持
- 掌握 CSS 文件导入、HMR、代码分割和压缩的工作方式

## 2. 评价

- Vite 对原生 CSS 的支持非常完善，无需任何配置即可使用
- CSS HMR 和代码分割是 Vite 的亮点功能，开发体验优于传统工具

## 3. CSS 文件导入

- Vite 原生支持 `.css` 文件的导入，无需安装任何 loader 或插件

```ts
// 直接导入 CSS 文件
import './styles/main.css'
```

- CSS 也可以在 HTML 中通过 `<link>` 标签引用：

```html
<link rel="stylesheet" href="./styles/main.css" />
```

- JS 中导入的 CSS 会被注入到页面的 `<head>` 中（开发环境），生产环境则提取为独立文件
- 支持 `@import` 语法，Vite 会自动处理 CSS 模块间的依赖关系

## 4. CSS HMR

- CSS 的 HMR 是开箱即用的，无需任何额外代码
- 修改 CSS 文件后，Vite 通过 WebSocket 通知浏览器，用新的 `<style>` 标签替换旧的
- 不丢失任何状态：只替换样式，不影响 DOM 结构和 JavaScript 状态
- 这是日常开发中最频繁体验到的 HMR 场景
- CSS Modules 和 CSS 预处理器（Sass/Less）同样支持 HMR

## 5. CSS 代码分割

- Vite 在生产构建时会自动进行 CSS 代码分割：
  - 每个组件/模块导入的 CSS 会被提取为独立的 CSS 文件
  - 动态导入的组件，其 CSS 也会按需加载
  - 多个模块共享的 CSS 会被提取为公共 CSS 文件
- 按需加载的 CSS 通过 `<link rel="stylesheet">` 标签动态插入
- 与 Webpack 的 `MiniCssExtractPlugin` 类似，但 Vite 开箱即用

## 6. CSS 压缩

- 生产构建时 Vite 自动压缩 CSS：
  - 默认使用 Lightning CSS（Rust 实现，速度极快）
  - 也可以使用 PostCSS + cssnano
- 压缩操作包括：
  - 移除空白和注释
  - 合并重复的规则
  - 缩短颜色值（如 `#ffffff` → `#fff`）
  - 优化选择器
- 可通过 `css.transformer`（实验性）配置选择 CSS 处理引擎（默认为 `'postcss'`）：

```ts
export default defineConfig({
  css: {
    transformer: 'lightningcss', // 或 'postcss'（默认）
  },
})
```
