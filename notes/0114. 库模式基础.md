## 1. 本节内容

- 了解 Vite 库模式的概念和用途
- 理解库模式与应用构建的区别
- 掌握库模式的适用场景

## 2. 评价

- 库模式是 Vite 为库开发者提供的专用构建模式
- 如果你要开发 npm 包、UI 组件库或工具库，库模式是最佳选择

## 3. 什么是库模式

- 库模式（Library Mode）是 `vite build --lib` 或配置 `build.lib` 的构建模式
- 将项目构建为可被其他项目消费的 npm 库
- 产物格式：
  - ESM（`.mjs` 或 `.js`）
  - UMD（同时支持 `<script>` 标签和 `require`）
  - CSS（自动提取）

```ts
export default defineConfig({
  build: {
    lib: {
      entry: 'src/index.ts',
      name: 'MyLib',
      formats: ['es', 'umd'],
      fileName: (format) => `my-lib.${format}.js`,
    },
  },
})
```

## 4. 与应用构建的区别

| 维度         | 应用构建               | 库模式                |
| ------------ | ---------------------- | --------------------- |
| 入口         | `index.html`           | JS/TS 文件            |
| 产物         | HTML + JS + CSS + 资源 | JS + CSS              |
| 外部依赖     | 全部打包               | 排除 peerDependencies |
| Tree Shaking | 对最终用户生效         | 对库自身生效          |
| 用途         | 部署到服务器           | 发布到 npm            |

## 5. 适用场景

- 开发 UI 组件库（如 Element Plus、Ant Design Vue）
- 发布工具函数库（如 lodash-es 的自定义版本）
- 开发可复用的业务模块
- 需要同时支持 ESM 和 UMD 两种消费方式的场景
