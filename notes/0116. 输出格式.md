## 1. 本节内容

- 了解库模式支持的各种输出格式
- 掌握 ES Module、CommonJS、UMD、IIFE 的区别和适用场景

## 2. 评价

- 不同格式服务于不同的消费方式，选择合适的格式很重要
- 现代库推荐以 ESM 为主格式，UMD 作为兼容格式

## 3. ES Module

- 现代 JavaScript 的标准模块格式
- 支持 `import`/`export` 语法
- 优势：支持 Tree Shaking、静态分析、按需加载
- 文件后缀：`.mjs` 或 `.js`（取决于 `package.json` 的 `type` 字段）
- 适用场景：现代打包工具（Vite、Webpack 5+）消费

## 4. CommonJS

- Node.js 的传统模块格式
- 使用 `require()`/`module.exports` 语法
- 文件后缀：`.cjs`
- 适用场景：Node.js 环境、旧版打包工具
- Vite 库模式支持 `'cjs'` 格式输出

## 5. UMD

- Universal Module Definition，兼容 AMD、CommonJS 和全局变量
- 可以通过 `<script>` 标签直接引入，也可以通过 `require()` 使用
- 需要指定 `name` 配置（全局变量名）
- 适用场景：CDN 引入、兼容各种环境

## 6. IIFE

- Immediately Invoked Function Expression，自执行函数
- 最简单的格式，直接将库挂载到全局变量
- 与 UMD 的区别：IIFE 不支持 AMD 和 CommonJS
- 适用场景：简单的 `<script>` 标签引入
