## 1. 本节内容

- 理解 Vite 开发服务器基于原生 ESM 的工作原理
- 了解浏览器如何直接加载模块
- 理解按需转换和请求驱动编译的机制

## 2. 评价

- 本节是理解 Vite "快" 的核心，建议反复理解"请求驱动编译"这个概念
- 与 Webpack "全量打包再服务" 的对比是关键，理解了这一点就理解了 Vite 的设计哲学

## 3. 基于原生 ES Modules

- Vite 开发服务器的核心是利用浏览器对 ES Modules 的原生支持
- 传统打包工具（如 Webpack）的做法：
  1. 启动时从入口文件开始，递归解析所有 `import` 语句
  2. 将所有模块打包成一个或多个 bundle 文件
  3. 浏览器加载 bundle，模块解析在打包阶段已完成
- Vite 的做法：
  1. 不做打包，直接将模块以 ESM 形式提供给浏览器
  2. 浏览器遇到 `import` 语句时，向 Dev Server 发起 HTTP 请求
  3. Dev Server 拦截请求，按需转换后返回
- 浏览器兼容性：所有现代浏览器都支持 `<script type="module">`

## 4. 浏览器直接加载模块

- 工作流程：
  1. 浏览器请求 `index.html`，Vite 返回根 HTML 文件
  2. HTML 中的 `<script type="module" src="/src/main.ts">` 触发模块请求
  3. Vite Dev Server 接收到 `/src/main.ts` 的请求，使用 Esbuild 将 TypeScript 转为 JavaScript，返回给浏览器
  4. 浏览器解析返回的 JS，发现 `import './App.vue'` 等语句，继续发起新的模块请求
  5. 每个新请求都会触发 Vite 的即时转换，逐个返回
- 这种"链式请求"的方式意味着：**只有用户访问到的页面/路由对应的模块才会被编译**
- 首屏加载速度与项目总模块数量无关，只与首屏需要的模块数量有关

## 5. 按需转换源码

- Vite Dev Server 本质上是一个**即时编译的中间层**
- 当浏览器请求某个模块时，Vite 执行以下转换流程：
  1. **路径解析**：将裸模块导入（如 `import vue from 'vue'`）重写为 `/node_modules/.vite/vue.js?v=xxx`
  2. **内容转换**：根据文件类型调用对应的转换器（Esbuild 转 TS、Vue Compiler 转 SFC 等）
  3. **依赖处理**：对 `node_modules` 中的模块，直接返回预构建后的产物
- 转换结果会被缓存，同一模块的后续请求直接返回缓存
- 这种按需转换带来了两个关键优势：
  - 启动极快：不需要等所有文件编译完
  - 内存占用低：只缓存实际请求过的模块

## 6. 请求驱动编译

- 这是 Vite 区别于传统打包器的**最核心概念**
- 传统打包器是"构建驱动"：先构建完整的模块依赖图，再提供服务
- Vite 是"请求驱动"：没有预先构建的过程，一切以浏览器的请求为触发点
- 形象的比喻：
  - Webpack 像是印刷厂：先把整本书排好版、印刷完，读者才能阅读
  - Vite 像是点菜：读者翻到哪一页，厨房才开始做那道菜
- 对开发体验的影响：
  - 项目启动时间从"与项目规模成正比"变为"基本恒定"
  - 无论项目有 100 个文件还是 10000 个文件，Dev Server 都能在秒级启动
  - 代价是首次访问某个页面时可能有短暂的编译延迟（通常在毫秒级别）
