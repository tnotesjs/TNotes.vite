## 1. 本节内容

- 了解渐进式迁移到 Vite 的策略
- 掌握小项目一次性迁移和大项目分阶段迁移的方式

## 2. 评价

- 渐进式迁移可以降低风险，适合大型项目
- 小项目建议一次性迁移，避免维护两套构建系统

## 3. 小项目一次性迁移

- 对于小型项目，直接替换构建工具：
  1. 安装 Vite 和相关插件
  2. 创建 `vite.config.ts`
  3. 迁移环境变量（前缀改为 `VITE_`）
  4. 迁移路径别名
  5. 删除旧的构建配置（webpack.config.js 等）
  6. 更新 `package.json` 的 scripts
  7. 测试所有功能

## 4. 大项目分阶段迁移

- 对于大型项目，分阶段迁移降低风险：
  1. **阶段一**：新模块使用 Vite 开发
  2. **阶段二**：将简单的页面迁移到 Vite
  3. **阶段三**：逐步迁移核心页面
  4. **阶段四**：完全移除旧构建系统
- 每个阶段都应充分测试后再进入下一阶段

## 5. 保留旧构建流程

- 迁移期间保留旧的构建流程作为 fallback：

```json
{
  "scripts": {
    "dev": "vite",
    "dev:legacy": "webpack serve",
    "build": "vite build",
    "build:legacy": "webpack --mode production"
  }
}
```

## 6. 双构建验证

- 迁移期间同时运行两套构建系统，对比产物：
  - 比较构建产物的体积
  - 比较页面渲染结果
  - 比较运行时行为
- 确保 Vite 构建的产物与 Webpack 构建的产物功能一致
