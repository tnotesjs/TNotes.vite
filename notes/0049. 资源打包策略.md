## 1. 本节内容

- 了解 Vite 对静态资源的打包策略
- 掌握小资源内联、Hash 命名、资源目录等配置
- 理解 `base` 配置对资源路径的影响

## 2. 评价

- 资源打包策略直接影响产物的缓存效率和加载性能
- 默认策略已经足够优秀，大部分项目不需要修改

## 3. 小资源内联

- 小于 `build.assetsInlineLimit`（默认 4KB）的资源会被 Base64 内联
- 内联的优势：减少 HTTP 请求数，避免小文件的网络开销
- 内联的劣势：增加 JS/HTML 文件体积，Base64 编码后体积增大约 33%

```ts
export default defineConfig({
  build: {
    assetsInlineLimit: 8192, // 8KB 以下内联
    // 设为 0 禁用内联
  },
})
```

- 图片的内联阈值：文件大小小于 `assetsInlineLimit` 且不是 SVG
- SVG 不受此限制，Vite 会将 SVG 作为独立文件处理

## 4. Hash 命名

- 构建产物中的资源文件默认带内容哈希，格式为 `[name]-[hash].[ext]`
- 内容哈希的优势：
  - 文件内容变化时文件名变化，浏览器自动获取最新版本
  - 文件内容不变时文件名不变，利用浏览器缓存（长期缓存策略）
- 自定义命名格式：

```ts
export default defineConfig({
  build: {
    rolldownOptions: {
      output: {
        // JS 文件
        entryFileNames: 'assets/js/[name]-[hash].js',
        chunkFileNames: 'assets/js/[name]-[hash].js',
        // 资源文件（图片、字体等）
        assetFileNames: 'assets/[ext]/[name]-[hash].[ext]',
      },
    },
  },
})
```

## 5. 资源目录

- 静态资源默认输出到 `dist/assets/` 目录
- 可通过 `build.assetsDir` 修改子目录名：

```ts
export default defineConfig({
  build: {
    assetsDir: 'static', // 输出到 dist/static/
  },
})
```

- 也可以在 `rolldownOptions.output.assetFileNames` 中为不同类型的资源指定不同子目录

## 6. CDN 路径

- 将资源部署到 CDN 时，需要配置 `base` 为 CDN 地址：

```ts
export default defineConfig({
  base: 'https://cdn.example.com/assets/',
})
```

- 构建后所有资源引用都会自动加上 CDN 前缀
- HTML 文件本身仍然部署在源站，资源从 CDN 加载
- 注意：CDN 地址必须以 `https://` 或 `//` 开头（不能以 `/` 开头）

## 7. `base` 配置

- `base` 配置决定所有资源的基础路径
- 不同场景的配置：

| 场景           | `base` 值                    | 说明             |
| -------------- | ---------------------------- | ---------------- |
| 域名根路径部署 | `'/'`                        | 默认值           |
| 子路径部署     | `'/my-app/'`                 | 如 GitHub Pages  |
| CDN 部署       | `'https://cdn.example.com/'` | 资源从 CDN 加载  |
| 相对路径       | `'./'`                       | 灵活但有兼容问题 |

- 动态配置（开发和生产使用不同的 base）：

```ts
export default defineConfig(({ command }) => ({
  base: command === 'serve' ? '/' : '/my-app/',
}))
```
