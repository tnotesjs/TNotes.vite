## 1. 本节内容

- 了解 Vue Router 与 Vite 的集成方式
- 掌握路由懒加载的配置
- 理解 History 模式下的部署配置

## 2. 评价

- Vue Router 是 Vue 项目的标配路由库，与 Vite 集成无需额外配置
- 路由懒加载是优化首屏加载速度的关键手段

## 3. 路由配置

- 安装：`npm install vue-router`
- 基本配置：

```ts
// src/router/index.ts
import { createRouter, createWebHistory } from 'vue-router'

const router = createRouter({
  history: createWebHistory(import.meta.env.BASE_URL),
  routes: [
    { path: '/', component: () => import('@/views/Home.vue') },
    { path: '/about', component: () => import('@/views/About.vue') },
  ],
})

export default router
```

- 在 `main.ts` 中挂载：

```ts
import { createApp } from 'vue'
import App from './App.vue'
import router from './router'

createApp(App).use(router).mount('#app')
```

## 4. 懒加载

- 使用动态 `import()` 实现路由级别的代码分割：

```ts
const routes = [
  {
    path: '/',
    // 懒加载：访问该路由时才加载组件代码
    component: () => import('@/views/Home.vue'),
  },
  {
    path: '/dashboard',
    // 懒加载：访问该路由时才加载组件代码
    component: () => import('@/views/Dashboard.vue'),
  },
]
```

- Vite 原生支持动态 `import()`，无需任何配置
- 构建时每个懒加载的路由会生成独立的 JS 文件（chunk）
- 首屏只加载当前路由对应的 chunk，减少初始加载体积

## 5. History 模式

- Vue Router 支持两种历史模式：
  - `createWebHistory()`：HTML5 History 模式（推荐）
  - `createWebHashHistory()`：Hash 模式
- History 模式的优势：
  - URL 更美观（无 `#`）
  - 更好的 SEO
  - 需要服务器端配合（配置 SPA fallback）
- Hash 模式无需服务器配置，适合简单的静态托管

## 6. 部署配置

- History 模式需要配置服务器的 SPA fallback，将所有路由请求重定向到 `index.html`
- Nginx 配置：

```nginx
location / {
  try_files $uri $uri/ /index.html;
}
```

- Vite 开发服务器内置 SPA fallback，开发时无需配置
- 预览服务器（`vite preview`）同样内置此功能
- 如果部署到子路径（如 `/my-app/`），需要设置 `base` 和 `createWebHistory` 的参数：

```ts
createRouter({
  history: createWebHistory('/my-app/'),
  // ...
})
```
