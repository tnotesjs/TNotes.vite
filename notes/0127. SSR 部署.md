## 1. 本节内容

- 了解 SSR 应用的各种部署方式
- 掌握 Node.js 服务、Serverless、Edge Runtime、Docker 的部署配置

## 2. 评价

- SSR 部署比静态部署复杂，需要一个 Node.js 运行环境
- 推荐使用 Nuxt/Next.js 的内置部署适配器简化配置

## 3. Node.js 服务

- 最传统的部署方式：在服务器上运行 Node.js 进程

```bash
# 构建
vite build

# 启动
node dist/server.js
```

- 使用 PM2 管理进程：

```bash
pm2 start dist/server.js --name my-ssr-app
```

## 4. Serverless

- 将 SSR 部署为 Serverless 函数（如 AWS Lambda、Vercel Functions）
- 优势：按需扩展、按调用计费
- Nuxt/Next.js 内置 Serverless 适配器

## 5. Edge Runtime

- 将 SSR 部署到 CDN 边缘节点（如 Cloudflare Workers、Vercel Edge Functions）
- 优势：极低延迟（用户就近访问）
- 限制：不支持完整的 Node.js API

## 6. Docker

- 使用 Docker 容器化 SSR 应用：

```dockerfile
FROM node:20-alpine
WORKDIR /app
COPY package.json pnpm-lock.yaml ./
RUN npm install -g pnpm && pnpm install --prod
COPY dist ./dist
EXPOSE 3000
CMD ["node", "dist/server.js"]
```

## 7. Nginx 反向代理

- Nginx 作为反向代理，将请求转发给 Node.js 服务：

```nginx
upstream ssr_backend {
  server 127.0.0.1:3000;
}

server {
  location / {
    proxy_pass http://ssr_backend;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
  }

  location /assets/ {
    # 静态资源直接由 Nginx 返回
    root /var/www/dist/client;
    expires 1y;
  }
}
```
