## 1. 本节内容

- 了解 SSR 中数据获取的方式
- 掌握服务端数据预取和状态序列化的流程
- 理解 XSS 防护和客户端状态恢复

## 2. 评价

- 数据获取是 SSR 中最复杂的部分之一
- 推荐使用 Nuxt/Next.js 的数据获取方案，手动实现容易出错

## 3. 服务端数据预取

- SSR 的数据预取流程：
  1. 服务端接收到请求
  2. 根据路由确定需要获取哪些数据
  3. 调用 API 获取数据
  4. 将数据注入到应用状态中
  5. 渲染 HTML 并将数据序列化到 HTML 中
- Vue 的数据预取（使用 Pinia）：

```ts
// 服务端
const pinia = createPinia()
app.use(pinia)
// 执行组件的 setup，获取数据
await renderToString(app)
// 序列化 Pinia 状态
const state = JSON.stringify(pinia.state.value)
```

## 4. 状态序列化

- 将服务端获取的数据序列化为 JSON，注入到 HTML 中：

```html
<script>
  window.__INITIAL_STATE__ = ${JSON.stringify(state)}
</script>
```

- 注意：序列化时需要处理特殊字符（如 `</script>`），使用 `serialize-javascript` 库

## 5. XSS 防护

- 状态序列化时必须防止 XSS 攻击
- 不要直接使用 `JSON.stringify`，因为它不会转义 HTML 特殊字符
- 使用 `serialize-javascript` 自动转义：

```ts
import serialize from 'serialize-javascript'

const script = `<script>window.__STATE__=${serialize(state, { isJSON: true })}</script>`
```

## 6. 客户端状态恢复

- 客户端 Hydration 时从 `window.__INITIAL_STATE__` 恢复状态：

```ts
// 客户端
const pinia = createPinia()
app.use(pinia)
// 恢复服务端状态
if (window.__INITIAL_STATE__) {
  pinia.state.value = window.__INITIAL_STATE__
}
```

- 确保客户端和服务端的状态一致，避免 Hydration Mismatch
