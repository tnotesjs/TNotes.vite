## 1. 本节内容

- 了解 Vite 项目的标准目录结构
- 理解每个核心文件和目录的作用
- 掌握 Vite 项目与传统 Webpack 项目在结构上的差异

## 2. 评价

- Vite 项目的目录结构非常简洁，体现了"约定优于配置"的设计理念
- 与 Webpack 项目相比，少了 `webpack.config.js`、`babel.config.js` 等大量配置文件
- `index.html` 位于项目根目录是 Vite 的一个重要特征，理解这一点很关键

## 3. `index.html`

- 位于项目根目录，这是 Vite 与 Webpack 最显著的结构差异之一
- Webpack 中 `index.html` 通常放在 `public/` 目录，由 `html-webpack-plugin` 生成
- Vite 中 `index.html` 是应用的入口，Dev Server 直接服务于这个文件
- 可以使用 EJS 模板语法或直接引用源码中的模块
- 典型内容：

```html
<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>My App</title>
  </head>
  <body>
    <div id="app"></div>
    <script type="module" src="/src/main.ts"></script>
  </body>
</html>
```

- 关键点：`<script type="module">` 让浏览器通过原生 ESM 加载入口脚本

## 4. `src`

- 存放项目的源代码，是最核心的目录
- 典型结构：

```
src/
├── main.ts          # 应用入口
├── App.vue          # 根组件（Vue）或 App.tsx（React）
├── components/      # 可复用组件
├── views/           # 页面级组件（配合路由使用）
├── assets/          # 需要被构建工具处理的静态资源（图片、字体等）
├── composables/     # 组合式函数（Vue）或 hooks（React）
├── stores/          # 状态管理（Pinia / Zustand 等）
├── utils/           # 工具函数
├── styles/          # 全局样式
├── router/          # 路由配置
├── types/           # TypeScript 类型声明
└── api/             # API 请求封装
```

- `src/assets/` 中的资源会被 Vite 处理（添加哈希、优化体积等），而 `public/` 中的资源则原样复制

## 5. `public`

- 存放不需要被构建工具处理的静态资源
- 该目录中的文件会被原样复制到构建产物的根目录
- 适用场景：
  - `favicon.ico`、`robots.txt` 等必须位于根路径的文件
  - 第三方脚本（如统计 SDK、广告代码）
  - PWA 的 `manifest.json` 和 Service Worker
  - 大体积的媒体文件（视频、PDF 等），避免被构建工具编码处理
- 在源码中引用方式：`/favicon.ico`（绝对路径，从根目录开始）
- 注意：`public/` 中的资源不会触发 HMR，修改后需要手动刷新

## 6. `vite.config.ts`

- Vite 的配置文件，位于项目根目录
- 支持的文件名（按优先级）：`vite.config.ts`、`vite.config.js`、`vite.config.mjs`、`vite.config.cjs`、`vite.config.mts`
- 使用 `defineConfig` 函数可以获得完整的 TypeScript 类型提示：

```ts
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'

export default defineConfig({
  plugins: [vue()],
  server: {
    port: 3000,
    proxy: {
      '/api': 'http://localhost:8080',
    },
  },
})
```

- 与 Webpack 的 `webpack.config.js` 相比，Vite 的配置文件通常简短得多，因为大部分功能开箱即用

## 7. `package.json`

- 项目的核心元数据文件，定义依赖、脚本、版本等信息
- Vite 项目中通常包含以下 scripts：

```json
{
  "scripts": {
    "dev": "vite",
    "build": "tsc && vite build",
    "preview": "vite preview"
  }
}
```

- 关键依赖：
  - `vite`：核心工具（通常是 devDependency）
  - 框架插件：`@vitejs/plugin-vue`、`@vitejs/plugin-react` 等
  - `typescript`：TypeScript 支持
- 注意区分 `dependencies` 和 `devDependencies`，`vite` 本身属于 devDependency

## 8. `tsconfig.json`

- TypeScript 的编译配置文件
- Vite 项目通常有两个 tsconfig 文件：
  - `tsconfig.json`：应用源码的 TS 配置
  - `tsconfig.node.json`：Node.js 环境的 TS 配置（用于 `vite.config.ts` 等构建配置文件）
- Vite 项目中 `tsconfig.json` 的典型配置要点：

```json
{
  "compilerOptions": {
    "target": "ES2020",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "jsx": "react-jsx",
    "strict": true,
    "resolveJsonModule": true,
    "isolatedModules": true,
    "esModuleInterop": true
  }
}
```

- `moduleResolution: "bundler"` 是 Vite 项目推荐的模块解析策略，兼容 ESM 和 bundler 行为
- `isolatedModules: true` 确保每个文件可以被单独转译（Oxc 转换器的要求）
